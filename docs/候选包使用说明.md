## 包内内容

- version.dll（补丁库）和 patch_load.exe（内存加载程序）。
- config.example.json（配置示例）：只含程序路径和视频参数。
- source.zip（对应提交的源码包）、第三方许可及详细说明。
- manifest.json（文件摘要清单）：记录源码提交和其余文件的安全摘要。

不包含设备标识、本地配置、官方安装包、日志、转储或分析数据库；安卓调试桥及投屏组件仍使用本机已有程序。

## 当前电脑启用

源码目录的第二修订在 build/revision2/Release（候选构建目录），旁边的根目录指针指向当前源码仓库，继续读取原有本地配置。本次已从此位置加载；不能叠加第二份，以后操作前需重新核对实际状态。

加载方式是临时内存加载，重启电脑或后台后会失效，不会开机自动启用。若当前后台没有补丁，可在授权后手动加载，无需再重启；若已加载其他候选，则需要先说明并取得重启授权，再更换版本。重启会中断现有远程连接，可能重新枚举显示器。持久化安装仍未开放。

## 在其他目录使用候选包

解压到独立目录，把配置示例复制为 config.local.json（本地配置），核对本机程序路径。要求 scrcpy（安卓投屏组件）5.0.1，配套 avcodec（视频解码库）63 和 avutil（多媒体工具库）61。配置放在补丁库旁边；不要复制本机开发用的根目录指针。

先确认后台中没有旧补丁，再从管理员终端运行以下命令。它只加载库，不会重启；加载成功后还需检查私有日志是否记录挂接启用。

```powershell
./patch_load.exe ./version.dll
```

如果提示另一个同名库已经加载，应先停止尝试，按照已约定的断连窗口重启后台。不要换目录重复加载。

## 当前加载与放目录加载的区别

当前由 patch_load.exe（加载程序）在管理员授权后，让官方后台进程载入 version.dll（补丁库）。补丁核对三个二进制摘要后，挂接实例列表、画面与输入接口；官方程序文件没有被改写，中继继续由原程序处理。该方式只在当前后台进程内生效。

候选库已经实现 version.dll（系统版本信息库）的代理入口，将正常接口转发到系统原库，再启动接入逻辑。本次静态核对宿主确实导入该库，渲染库也是直接导入项，因此具备研究“将补丁放入后台程序同目录后自动加载”的基础；目前尚未正式验证这种启动方式，安装脚本仍拒绝持久化安装。

“不再需要手动运行加载程序”和“只放一个库文件即可使用”是两项要求。当前代码强制读取 config.local.json（本地配置），另需本机 ADB（安卓调试桥）、scrcpy（安卓投屏组件）的服务文件与解码库。开发目录通过 patch-root.txt（根目录指针）找到仓库配置；直接移动库而不提供对应配置位置，会在初始化时失败。因此现有候选不能宣称是单文件即用，打包、配置发现与依赖安排仍需单独完善。

本次仅核对实现，没有将补丁复制到官方目录或改变自动加载方式。原候选归档保持不变，其中的说明仍对应原代码提交。
