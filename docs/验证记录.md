## 首次实机异常

09:30:48（本机时间）日志显示匹配版本的挂接已启用。09:31:08（本机时间）系统应用错误事件记录后台在项目构建的版本代理库中栈溢出，异常编号为 0xc00000fd（栈溢出），相对偏移为 0x38e97（栈探测指令位置）。后台随后自动创建新进程。该偏移只能说明栈空间耗尽，不能单凭它认定某个函数递归。

用户反馈主桌面分辨率异常、副屏消失，进一步说明两块外接显示器当时关闭，屏幕重置后只剩笔记本内置屏幕。项目没有主动调用显示配置接口，但后台崩溃与显示变化先后发生，必须作为本次加载的实机影响保留。用户随后要求继续排查；当前保持现有显示状态，不自动修改。

首次加载前没有重启、没有停止远程服务，也没有覆盖官方安装文件。以上事实不能消除加载本身的崩溃风险。修复前停止再次实机注入；安装脚本的安装动作也暂时拒绝执行。

## 已复现并修复的崩溃原因

管理员授权后已复制本机转储。异常线程的第二参数为二，表明当时在处理线程附加通知；栈顶返回位置对应代理入口的栈探测指令。旧入口虽然先判断通知类型，编译器仍在函数序言无条件分配其大路径数组；静态线程局部状态使禁用通知不可靠，显卡驱动的小栈线程因此在进入代理入口时溢出。

独立代理检查加载旧库并创建六十四千字节栈线程，得到相同的栈溢出退出编号。修正版缩小入口数组，将其他大路径和摘要数组移到堆，显式为工作线程预留一兆字节栈；同一检查连续八轮线程创建退出通过。协议、纹理和管理接口检查也通过。随后仍须单独确认官方手机端行为。

同时修复了文字超过投屏协议三百字节上限的问题、静态画面十秒无新帧就被误判断连的问题，以及销毁会话时持锁等待可能阻塞重入回调的问题。没有在安卓设备上注入触控验证。

## 官方手机端仍需补上的证据

1. 崩溃根因已经独立复现并修复；继续观察修正版在真实后台中的稳定性。
2. 查清实例管理实际使用的库、在线状态及批量设置格式。仅调整状态数字或摘要白名单不算修复。
3. 在隔离程序检查原实例回退、虚拟列表和渲染生命周期，再决定是否加载到正式后台。
4. 加载会影响当前远程对话，须提前说明；任何重启、停止服务都须另行提前说明，脚本不得自动执行。
5. 官方手机端依次确认列表、画面、单点、多指、切换与重连，并逐项记录观察，不把协议断言写成实机通过。

## 复查命令

```powershell
cmake -S . -B build/candidate -G 'Visual Studio 18 2026' -A x64
cmake --build build/candidate --config Release
ctest --test-dir build/candidate -C Release --output-on-failure
node tools/explain-source.mjs --check
./tools/install.ps1 -Action Status
```

只读设备检查使用 build/candidate/Release/bridge_check.exe device（本地设备画面检查）。它会上传服务文件并创建临时转发，不发送触控；不会进入官方手机端。设备适配没有变化时无需反复运行。

本地诊断资料保存在 private/diagnostics（私有诊断目录），不随仓库提交。完整转储可能包含进程敏感信息，留在本机分析，不上传。
