# 手机端反馈对应的第二修订

2026 年 11 月 11 日，用户确认官方手机端已经出现新增设备并能看到画面，同时反馈五项缺陷。第二修订完成代码修改和独立检查，并在用户重启电脑后约于 19:17（本机时间）正式加载；用户本轮复测确认五项正常，打开多开管理界面时仍会闪一下。这里记录的是依据与验证边界；准确源码行及完整代码见同目录《实现详解.md》。

## 预览颜色

解码后的内部像素顺序为 BGRA（蓝绿红透明度）。原截图路径直接复制给宿主，但宿主最终交给 PNG（无损图片）编码器的是 RGBA（红绿蓝透明度）四通道字节。红蓝因此颠倒，不能通过改变视频色彩矩阵解决。

宿主相对地址 0x591f50（截图回调实现）经 0x591900（复制截图）、0x67b70（图片编码入口）到 0xd30000（编码包装），最终在 0xd2e9c0（四通道图片编码）传给编码器。第二修订只在截图输出边界交换红蓝；共享纹理依据目标格式处理，内部画面保持原顺序。

独立检查明确写出红、绿、蓝、黄、品红、青六个像素及预期字节，同时覆盖缩放和竖屏不旋转，避免只拿同一转换函数生成期望值。

## 偶发连接错误

原通道编号等于固定高位值加设备索引。预览和正式画面请求同一设备时得到相同编号，后一次创建覆盖前一个，随后销毁会移除对方。正式日志实际出现了同一设备同时创建两次、连接和销毁交错的记录。

第二修订改成每次创建独立递增句柄，旧句柄在销毁后明确拒绝，不能交回原渲染库。安卓投屏服务编号也使用独立原子计数，避免同毫秒启动相同设备时复用套接字名称。启动等待、宿主回调及线程退出均放在生命周期锁外。

解码线程仅更新本地尺寸。连接线程在首帧就绪后通知宿主；逐帧请求检测后续尺寸变化并通知。这样宿主回调重入销毁时，不会由解码线程等待自己退出。

独立进程对同一真实设备执行三轮双通道并行连接；每轮确认两个预览成功、销毁第一个后第二个仍能查询及截图。检查不发送触控，不加载到正式后台。它覆盖了本次明确竞态，不能保证所有网络连接错误均已消失。

## 三个导航按钮

官方安卓安装包的原生键转换在相对地址 0x83df0（导航键转换）使用返回码 158（原生返回键）、主页码 172（原生主页键）及任务码 580（原生任务键）。分别应注入安卓键码 4（返回）、3（主页）和 187（最近任务）。旧代码漏掉后两项。

另外，官方工具栏的主页按钮实际通过 SendTabMangeToRoom（发送主页管理操作）请求到电脑端，并触发 tab_manage（主页操作）。因此只增加键映射仍不足以修复三个按钮。第二修订也将这条系统操作转换为主页按下和抬起；它与上下滑动切换设备无关。

参考官方手机反编译的 ScreenToolbarFragment（屏幕工具栏）中三个按钮分支：返回发 BACK（返回）按下抬起，主页发单独管理消息，任务发 MENU（最近任务）按下抬起。原生接口也支持直接主页键，所以保留两种路径。独立检查核对实际输出消息的动作与安卓键码，没有操作用户设备；正式加载后，三个按钮由用户本轮手机复测确认正常。

## 横屏和上下滑动切换

官方 ScreenSurfaceFragment（屏幕显示页）根据视频角度对一百八十取余决定手机方向：非零进入横屏，零进入竖屏。原补丁永远上报零度，即使安卓画面已经是横向。官方 ScreenToolbarFragment（屏幕工具栏）又在竖屏时将滚动指示器设为空，因此切换手势没有入口。

第二修订使用规范化竖向存储配合角度。以当前 1280×720（横向画面尺寸）为例：

| 数据 | 第二修订约定 |
|---|---|
| 解码后的当前画面 | 宽一千二百八十，高七百二十，保持正常朝向。 |
| 共享纹理和显示元数据 | 宽七百二十，高一千二百八十，角度九十度。 |
| 写入共享纹理 | 将当前横屏画面顺时针旋转九十度。 |
| 预览截图 | 使用当前朝向，输出红绿蓝透明度。 |
| 安卓触控 | 把手机发送的规范化原始坐标转回当前横屏坐标，并使用当前解码尺寸。 |

官方手机 MuMuManager::OnTouchUpdate（模拟器触点更新）位于相对地址 0x9ec20（触点更新实现）。九十度分支把当前画面的归一化横纵坐标转换为原始横坐标等于一减当前纵坐标、原始纵坐标等于当前横坐标。补丁执行逆变换：当前横坐标等于原始纵坐标，当前纵坐标等于当前高度减一再减原始横坐标。

电脑串流函数相对地址 0xe15dc0（模拟器捕获任务）会把九十度变为二百七十度后创建捕获帧，与上述存储约定配套。不能只把角度改成九十度而保留原像素和输入坐标。竖屏设备则保持零度和原尺寸；解码尺寸改变时释放旧触点，随后通知新的元数据。

管理设置取消固定的一千零八十乘一千九百二十占位值，未连通前使用窗口尺寸，首帧后采用真实解码尺寸。虚拟在线状态保持三；手机状态映射将三和四认定为运行中，并据此构建切换列表，不应凭猜测改状态数字。

本地检查覆盖横屏四角触控、明确六色非方形旋转、两种共享句柄和两种通道顺序、竖屏保持原样及尺寸变化释放触点。用户本轮手机复测已确认横屏与工具栏上下切换正常；四角定位和多指仍没有单独的实机记录。

## 本轮手机复测与剩余现象

针对预览颜色、进入画面、返回／主页／最近任务、横屏和上下滑动切换，用户回答：“没有问题，除了刚进来的时候会闪一下画面，其他功能一切正常。”随后澄清：“刚进来 指打开多开管理界面。”因此五项记为本轮用户实测通过，闪屏记录在打开多开管理界面这一操作下。

目前没有定位闪屏涉及的具体组件或原因。保留这一现象，不凭描述认定是纹理、旋转或客户端切换导致；本轮结果也不替代多指、长时间运行和其他环境的专项验证。

## 启用与保留

此前正式后台加载 build/candidate/Release/version.dll（首个修正版库）。用户重启电脑后，同意试用位于 build/revision2/Release/version.dll（第二修订候选库）的新版；加载程序返回零，日志确认挂接启用。该候选库现已被加载，不原地覆盖，也不卸载已有挂接。加载器会拒绝另一路径的第二个同名补丁。

更换已加载版本前仍需要先重启后台，会中断当前远程连接；本次电脑已由用户重启，因此手动加载时没有再重启后台。内存补丁不会随电脑或后台重启保留，当前没有开机自动加载。候选提交、归档摘要及后续检查见《续接记录.md》。分析工具、安装包、日志、转储和安卓临时服务文件均保留在本地，不进入提交或交付包。
