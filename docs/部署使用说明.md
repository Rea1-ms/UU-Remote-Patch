# 部署说明

部署包里是一个 `version.dll` 和一个 `uu-adb-patch` 文件夹。准备好依赖和配置，复制到 UU 后台旁边即可；不需要安装器，也不用每次运行注入程序。

仅适配 Windows x64、UU 被控端 **4.46.0.4716** 的指定构建。补丁会核对三个官方组件的完整摘要，版本号一样而文件不同也不会启用。手机继续使用官方客户端和中继。

## 准备依赖

下载 [scrcpy 5.0.1 Windows x64](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1)，将压缩包里的文件完整放进 `uu-adb-patch/runtime/scrcpy/`。不要直接连同压缩包的外层文件夹一起放进去。这个目录中应当能直接找到：

- `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll`；
- `scrcpy-server`、`avcodec-63.dll`、`avutil-61.dll`，以及上游包中的其他配套 DLL；
- 上游随附的许可证与声明。

也可以在配置中指向已有的依赖目录。本项目的部署包不捆绑这些运行库，不能混用其他主版本的服务和解码库。

设备需要开启 ADB 调试并完成授权。无线调试先配对；传统网络 ADB 需要设备已经开启相应端口。

## 配置

部署包自带一份通用的 `uu-adb-patch/config.local.json`，不含开发者的设备信息：

```json
{
  "adb": "runtime/scrcpy/adb.exe",
  "scrcpy": "runtime/scrcpy",
  "connect": [],
  "fps": 30,
  "max_size": 1920,
  "bit_rate": 8000000
}
```

相对路径以配置文件所在目录为起点，与终端工作目录无关。中文、空格和绝对路径均支持。USB 设备通常保留默认配置即可。

使用已有的依赖目录时，可以只改下面两个字段，其余设置保留：

```json
{
  "adb": "D:/Program Files/scrcpy/adb.exe",
  "scrcpy": "D:/Program Files/scrcpy"
}
```

JSON 路径建议使用 `/`。如果使用反斜杠，每个 `\` 都要写成 `\\`；单个 `\` 会被当作转义符，可能导致解析失败或路径错误。`adb` 填 `adb.exe` 的路径，`scrcpy` 填包含 `scrcpy-server` 和解码库的目录，不能填 `scrcpy.exe`。

网络设备在 `connect` 中填写自己的地址和端口，例如 `["192.0.2.1:5555"]`，这里的地址仅作示例。补丁会尝试连接尚未在线的设备，ADB 服务重启后也会重试；它不会代替设备开启调试端口或完成配对。

`fps` 是帧率，`max_size` 是画面最长边，`bit_rate` 是视频码率。可以先用默认值。

## 复制到 UU 目录

将部署包中的 `version.dll` 和整个 `uu-adb-patch` 文件夹复制到包含 `GameViewerServer.exe` 的目录。默认路径是 `C:/Program Files/Netease/GameViewer/bin`，写入时通常需要管理员权限。

必须与 `GameViewerServer.exe` 同级，不是上一级 `GameViewer` 目录。上一级的启动器所在位置不能代替后台目录；用户曾因少放一层而没有加载补丁，移动到 `bin` 后确认有效。

```text
bin/
├─ GameViewerServer.exe       # UU 原有文件
├─ version.dll               # 补丁入口
└─ uu-adb-patch/
   ├─ config.local.json      # 设备和画面设置
   ├─ runtime/
   │  └─ scrcpy/             # scrcpy 压缩包里的文件直接放在这里
   │     ├─ adb.exe
   │     ├─ AdbWinApi.dll
   │     ├─ AdbWinUsbApi.dll
   │     ├─ avcodec-63.dll
   │     ├─ avformat-63.dll
   │     ├─ avutil-61.dll
   │     ├─ disconnected.png
   │     ├─ libusb-1.0.dll
   │     ├─ LICENSE.txt
   │     ├─ open_a_terminal_here.bat
   │     ├─ scrcpy-noconsole.vbs
   │     ├─ scrcpy-server
   │     ├─ scrcpy.exe
   │     ├─ scrcpy.png
   │     ├─ SDL3.dll
   │     └─ swresample-7.dll
   ├─ README.md
   ├─ LICENSE               # 本项目的 MIT 许可证
   ├─ THIRD_PARTY.md
   ├─ licenses/
   │  ├─ minhook.txt
   │  ├─ json.txt
   │  └─ ffmpeg.txt
   └─ manifest.json
```

已有同名 DLL 或旧配置目录时，先退出后台并将旧文件改名备份，不要直接合并覆盖。目录中不能保留开发用的 `patch-root.txt`，它会让补丁优先读取旧开发目录；如果有，将它移开保留。

复制完成后正常重启被控端或电脑。**这会断开 UU 远程连接**；正在远程操作时，先安排好重新连接的方式。之后只要官方后台正常启动，补丁就会一起加载。补丁不单独建立服务或开机任务。

复制部署本身不要求 PowerShell 7。仓库里的 `tools/install.ps1` 是之前保留的开发安装工具，不随新部署包分发；它生成的安装记录不用于判断手动复制的文件。

## 查看结果

手机重新打开多开管理，应该能看到 ADB 设备。安装后在 `bin/uu-adb-patch/config.local.json` 修改配置，重启后台后生效。

运行记录在 `bin/uu-adb-patch/private/` 下，按后台进程分别生成。日志出现 `hooks active for host 4.46.0.4716` 表示挂接已启用；还需要检查手机实际显示和操作。没有设备时，先确认 ADB 能看到已授权设备，以及网络地址和端口正确。

当前主要手机功能已经用户复测确认，复制部署到正确目录后也已由本机用户确认有效。自动加载与配置目录选择另有独立检查；其他电脑尚未实测，多开预览闪烁尚未解决，多指和长期稳定性未做专项验证。

## 停用、恢复和升级

停用时退出 UU 后台，将 `bin/version.dll` 改名为 `version.dll.disabled` 或移到安装目录之外，再启动后台。配置、依赖和日志可以保留。恢复时把 DLL 放回原位，再次启动即可。

当前进程不支持热卸载；只关客户端窗口不一定退出后台。不要从其他路径叠加加载第二份补丁。升级补丁也要先退出后台，再备份旧 DLL 和配置目录。

UU 自身升级后，摘要不匹配时补丁会继续转发系统版本接口，但不再挂接。更新器可能整理安装目录，届时需重新检查文件并等待相应版本的适配。

## 包内保留的文件

`LICENSE` 是本项目的 MIT 许可证，`THIRD_PARTY.md` 和 `licenses/` 是第三方声明与完整许可证，请随 DLL 一起保留。`manifest.json` 给出本包对应的源码提交、部署方式和文件摘要。部署包不含截图、开发文档、注入工具、本机设备映射或诊断资料。
