# 安卓接入补丁维护

## 每次先读

- 仓库根目录 README.md（项目说明）：确认当前交付阶段。
- 仓库根目录 docs/验证记录.md（验证记录）：区分实际通过、待验证和已知限制。
- 仓库根目录 docs/续接记录.md（当前决定与候选定位）：确认用户是否暂停启用、已保留候选和下一次续接的边界；记录的进程状态只是历史观察，执行前再核对。
- 用户本轮对连接、重启、设备操作及文件保留的要求优先于本技能。

## 按任务读取

| 当前任务 | 读取位置与做法 |
|---|---|

| 实例列表和状态 | 读 src/common.cpp（设备发现）与 src/hooks.cpp（接口挂接）；检查列表容量、稳定索引、在线状态和原实例的回退。 |

| 构建、安装和恢复 | 读 CMakeLists.txt（构建定义）、tools/install.ps1（安装恢复脚本）和 tools/patch-load.cpp（免重启加载程序）；按脚本处理文件，不手工拼接停止服务命令。 |

| 手机复测反馈 | 读 docs/验证记录.md（验证记录）、docs/续接记录.md（当前决定）与 docs/手机端兼容修复.md（手机兼容说明）；按本轮实际询问的项目记录用户原话及后续澄清，保留剩余现象；仅整理结果时使用文档维护路径。 |
| 其他本项目工作 | 先读相关源码及 docs/验证记录.md（验证记录），选择最小必要检查；不默认重做全部调查。 |

## 已知易错点

- 用户可能通过当前远程连接聊天。任何重启、停止后台或停止服务前先说明会断连；免重启仅适用于确认没有补丁的后台首次加载，不能用于换版本叠加挂接。授权窗口取消后，等用户明确要求再发起。
- 用户明确“暂不重启、保留候选包”后，将决定写入续接记录；后续的文档整理不视为重新启用授权，也不再次催问重启。用户之后明确改变决定，才进入启用流程。
- 独立解码成功只能证明本地采集；手机显示、点击、滑动、多指、切换和重连需要各自的证据。每条结论注明用户实测、正式日志、离线协议依据或独立断言；候选未加载时不能写成手机问题已消失。
- 用户说“其他功能正常”时，只更新本轮明确询问的复测项目；闪屏等现象记录具体发生界面，采用用户最新澄清，未取证前不猜测根因，也不扩展为多指、长期稳定或所有设备均通过。
- 共享纹理由原串流组件提供。写入端取得键零、写入后释放键一；原组件取得键一后释放键零。原始截图仅用于诊断，不作为连续视频完成的依据。
- 渲染配置是八个空格分隔字段；进程号和显卡编号来自当前运行环境，不能复制调查样本后硬编码。
- 内部字符串返回空间需要符合宿主布局。当前虚拟实例名保持在十五字节以内，避免跨运行库堆释放。
- 首次实机在小栈显卡线程的线程附加通知中栈溢出。入口中的大数组即使写在条件返回之后，也可能在函数序言分配；静态线程局部变量会使禁用线程通知失败。修改加载逻辑后运行代理的小栈线程检查，不能只检查首次加载。
- 不在生命周期锁内调用宿主回调或等待解码线程退出；回调可能重入，销毁时先移出会话，再释放锁并合并线程。
- 预览截图要求 RGBA（红绿蓝透明度），内部帧为 BGRA（蓝绿红透明度）；只在输出边界转换。使用明确颜色常量检查，不仅比较同一转换函数的输出。
- 官方工具栏主页走 tab_manage（主页操作），返回和最近任务走原生键码一百五十八和五百八十。该系统操作不是上下分页；直接主页键码一百七十二也需兼容。
- 横屏要求竖向存储、九十度角和逆向输入变换配套。手机竖屏会关闭工具栏上下切换入口；先核对元数据和几何，不随意改运行状态数字。
- 同设备的预览与正式画面会并发创建；句柄及安卓服务编号都要独立。使用管理检查的 video（视频检查）模式验证双通道、回调重入与独立销毁。
- 一次连接错误先核对通道身份、首帧、元数据回调和销毁时序，不把每条“视频断开”都算意外失败；主动销毁也会写相同日志，编号竞态修复不能证明所有连接问题均已消失。
- 原管理与渲染接口的签名以本机反汇编和调用点为准；游戏脚本中的外部截图接口不能替代共享纹理协议。
- 不删除源文件、缓存或备份。停用补丁采用改名；安卓临时服务关闭自动删除。完成后提醒用户保留的缓存位置。
- 设备地址、标识、安装包和运行日志留在忽略目录。提交前检查待提交差异，不提交本地配置、环境变量文件及凭据。

## 代码变更的验证与交付

仅整理文档或技能时，按上表的文档维护路径处理：运行逐行说明的 --check（核对）动作、差异格式检查及待提交内容检查，再独立提交；不进入下面的构建与加载流程。

1. 先检查现有差异和运行中的补丁位置；已加载的库不要原地覆盖构建。
   已加载旧版时不能从其他目录叠加新版。先完成候选验证，再说明重启会断连并等待用户授权；不能把首次免重启加载流程套用于换版本。
   已生成且用户要求保留的候选包、对应二进制及摘要保持原样；后续代码修改另建候选目录。仅文档或技能更新独立提交，不为更新说明覆盖旧包。
2. 在独立候选构建目录编译。编译失败先修复具体错误，再继续。
3. 运行已有协议、纹理和代理检查；列表适配变更运行独立管理检查，设备适配变更再运行只读设备检查。
4. 安装前核对宿主版本、二进制摘要和同名代理库；摘要变化时保留原程序并重新调查。
5. 记录检查命令、返回结果及证据边界。手机端没有实际观察到的项目仍记为待验证。
6. 更新逐行说明与验证记录；提交前运行 tools/check-staged.mjs（待提交内容检查脚本），它核对私有目录、当前设备标识和常见凭据形态；再人工检查差异与打包清单后交付。

汇报采用一句结论，加最多三个短点：本轮结果、实际验证、仍需用户处理的具体事项。未完成的端到端验证须明确写出。
